GitHub Pages 博客搭建避坑指南

2026-05-14

最近搭建了自己的 GitHub Pages 个人博客，过程中踩了不少坑，整理了一份避坑指南，分享给想要搭建个人博客的朋友，希望大家能少走弯路，快速拥有自己的免费博客。

首先说最容易踩的坑——路径问题，这也是很多人出现 404 报错的核心原因。GitHub Pages 对路径大小写敏感，文件夹和文件名必须全小写，比如我用的 posts 文件夹，不能写成 Posts 或 POSTS，否则会找不到文件。另外，链接建议用根路径写法，比如 /posts/article1.html，比相对路径更稳定，不容易出错。

其次是文件命名，首页必须命名为 index.html，这是 GitHub Pages 默认的首页文件，少一个字母、多一个空格都会导致首页无法正常显示。文章页面的命名也建议统一规范，比如 article1.html、article2.html，方便后续管理，避免出现中文文件名，容易导致乱码或无法访问。

还有一个容易忽略的点，就是提交文件后，GitHub Pages 部署需要时间，一般1-5分钟，不要刚提交就着急访问，耐心等几分钟再刷新，很多时候不是配置错了，只是还没部署完成。如果部署后还是无法访问，可以去仓库 Settings → Pages 查看部署状态，有没有报错提示。

最后，GitHub Pages 只支持静态文件，不能运行后端代码，所以不要尝试放 PHP、Java 等文件，没用且会报错。如果只是用来记录日常、分享笔记，纯静态的 HTML 就足够了，简单、稳定、免费，还不用维护服务器。

总结一下，搭建 GitHub Pages 博客，核心就是注意路径、文件名规范，耐心等待部署，避开这几个坑，就能顺利拥有自己的个人博客啦。
